# T8 — In-world roster on Characters, and a guard against player names

| | |
|---|---|

| Depends on | **pnp-crawl plan C4** (`export_roster.py`) |

| Size | M |

## Goal

1. Generate a committed `knowledge/roster.yaml` with **in-world** facts per
   player character: name, concept id, team letter, class, active since and
   until. It is derived from pnp-crawl's rosters, not from the LLM.
2. Character concepts get `team`, `class`, `active_since`, `active_until`.
3. A local-only check counts real player names in concept titles, aliases
   and prose, with a ratchet that may only go down. It gets its list from a
   **private** file that never enters this repo.
4. A helper prints `alias_block:` suggestions for every alias that contains
   a player name.

## Why

- Player names leak into canon today: aliases like "<player> (Lindo Laut)",
  "<player> (Cookie)", "<player> (Dodo)"; a player name autolinked as an in-world actor
  in `deities/bodrak.md`; 10 player-name occurrences in prose.
- The bundle can't say who plays whom or which PCs are dead. Cookie was
  replaced by Lunara (same seat) and nothing records it.
- `Miqo` vs `Miko`: the speaker label (pnp-crawl roster) and the GM's
  spelling differ, which minted two Character concepts. Fixing the label is
  pnp-crawl C4's human step. Here, a `merge:` rule after the GM decides.

## Privacy rule (D1)

| Data | Where it may live |
|---|---|
| Character name, class, team, since/until | `knowledge/roster.yaml` (committed) |
| Real player names / keys | **only** pnp-crawl's gitignored `groups/roster_private.json`, read at runtime via `PNP_ROSTER_PRIVATE` |

Never print a player name into a committed file, a log line that gets
committed, or a test name. Assertion messages may show them: they only run
locally.

## Steps

### 1. Branch

```bash
git fetch origin && git switch -c feat/roster-player-guard origin/main
```

### 2. `services/kb/sync_roster.py` (new script, style of `rules_doctor.py`)

- Input: `--from <path>` (default
  `Path(__file__).resolve().parents[3] / "pnp-crawl" / "groups" / "roster_public.json"`).
  The format is defined by pnp-crawl C4:
  ```json
  {"characters": [{"name": "Lindo Laut", "class": "Fee Barde", "group": "Team-A",
                   "since": null, "until": null}]}
  ```
- Team letter: `Episodes.load(paths.episodes_path)._teams`. Expose a public
  `Episodes.team_letter(group) -> str | None` (T2 added `_teams`; add the
  method there).
- Concept id: match `name` against the registry `entities:` with
  `type: Character`, by canonical name, then by alias (case-insensitive),
  then by `slugify`. Unmatched rows are written with `concept_id: null` and
  listed on stderr. **Don't invent ids.**
- Output: `knowledge/roster.yaml`, with a header comment ("GENERATED by
  services/kb/sync_roster.py from pnp-crawl's roster export. In-world
  facts only -- no player names (docs/plans/T00 D1).") and a
  `characters:` list sorted by `(team, name)`.
- `--check` mode: exit 1 if the file would change (for CI-style use).

### 3. Load and emit

- `src/pnp_okf/roster.py` (new, small):
  ```python
  def load_roster(knowledge_root: Path) -> dict[str, dict]:
      """``concept_id -> {team, class, active_since, active_until}`` from roster.yaml."""
  ```
  Skip rows with `concept_id: null`. Drop `None` values.
- `cli.py`: `roster = load_roster(paths.knowledge_root)`. In the
  `emit_entity` call, merge `roster.get(entity.concept_id)` into the
  `world_state` dict from T7. Better: add a separate keyword
  `extra_frontmatter: dict | None` to `emit_entity` that both T7 and T8
  feed, so T7's parameter isn't overloaded. If T7 already merged with
  `world_state=`, add `extra_frontmatter` now and route both through it in
  this PR.
- Only `characters/` concepts receive roster fields. Assert it in a test.

### 4. Private player-name guard

- `src/pnp_okf/validate.py`, a new function (not part of `validate_bundle`,
  so `pnp validate` doesn't depend on a private file):
  ```python
  def player_name_hits(bundle_dir: Path, player_names: list[str]) -> list[tuple[str, str, str]]:
      """(concept_id, where, name) for each real player name found.

      ``where`` is "title", "alias" or "body". Whole-word, case-sensitive
      matches of names with >= 3 characters; prose inside "# Belege" is
      skipped (it quotes speaker labels on purpose).
      """
  ```
- `load_private_player_names() -> list[str] | None`: read the JSON path in
  env `PNP_ROSTER_PRIVATE` (`{"player_names": [...]}`); `None` if unset or
  missing.
- Test in `tests/test_bundle_invariants.py`:
  ```python
  # Ratchet: real player names in titles/aliases/prose (T8). Measured <date>: <N>.
  # Private list -- see docs/plans/T8. Only ever lower this.
  PLAYER_NAME_BASELINE = <N>

  def test_player_names_only_go_down():
      names = load_private_player_names()
      if names is None:
          pytest.skip("PNP_ROSTER_PRIVATE not set -- player-name list is private, local only")
      hits = player_name_hits(BUNDLE, names)
      assert len(hits) <= PLAYER_NAME_BASELINE, hits[:10]
  ```
  The skip reason deliberately differs from `"no bundle checked out"`, so
  CI's `PNP_REQUIRE_BUNDLE=1` doesn't turn it into an error.
- A unit test of `player_name_hits` on a tmp bundle with a **fake** name
  list (`["Alice"]`): it finds the title, alias and body hits, and skips
  `# Belege`.

### 5. Alias-block suggestions: `services/kb/player_alias_doctor.py` (new script)

It reads the private list and the bundle, and prints a YAML `alias_block:`
snippet: `concept_id: [alias, ...]` for every alias containing a player
name, ready to paste into `knowledge/entity_rules.yaml`. It writes nothing
itself. Mention in its docstring that the output contains player names, so
it is meant for the terminal only. Paste only the *alias strings* into the
rules file. The aliases already exist in the committed bundle, so blocking
them adds no new exposure.

## HUMAN RUN

1. In pnp-crawl: `python export_roster.py` (C4). Both JSON files are
   written; the private one is gitignored.
2. Here: `python sync_roster.py`. Review `knowledge/roster.yaml`. Every
   PC should be matched; fix unmatched rows with `merge:` or
   `canonical_name:` rules, or with the GM's Miqo/Miko decision.
3. Set `PNP_ROSTER_PRIVATE` in `.env` to the private JSON path, run the
   ratchet test once to measure `<N>`, and commit the baseline.
4. Run `player_alias_doctor.py`, paste the `alias_block:` entries, and do a
   warm `pnp run`. The ratchet should drop. Lower the baseline with a
   comment.
5. Remaining prose hits need re-synthesis or extraction rules (B2). Leave
   them under the ratchet.
